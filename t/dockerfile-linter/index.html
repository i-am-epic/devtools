Dockerfile Linter

The checks that actually bite: images that rebuild from scratch on every code change, containers running as root, and unpinned tags.

Open Dockerfile Linter →

What it does

Catch cache-busting layer order, missing USER, latest tags and other Dockerfile mistakes. It runs entirely in your browser — your input never leaves your machine, so it is safe to use with data you would not paste into a hosted service.

Example input

FROM node:latest

WORKDIR /app

COPY . .
RUN npm install
RUN apt-get update
RUN apt-get install -y curl

ADD https://example.com/tool.tar.gz /tmp/

ENV API_KEY=sk-supersecret

EXPOSE 3000
CMD npm start

How to use it

  1. Open Dockerfile Linter and paste or type your input.
  2. The result appears as you type.
  3. Copy the result, or save it to a file.

Things worth knowing

These are heuristics over the instruction list, not a full parse — heredocs, line continuations inside strings and BuildKit-specific syntax may confuse them. For CI, run hadolint as well.

Frequently asked questions

Is Dockerfile Linter free to use?

Yes. Every tool on this site is free, needs no account, and has no usage limits.

Does Dockerfile Linter upload my data?

No. It runs entirely in your browser using JavaScript. Your input is never sent to a server, which makes it safe for data you would not paste into a hosted tool. The two exceptions across the whole site (the Azure Service Bus relay and the IP lookup) are documented and opt-in.

What should I watch out for when using Dockerfile Linter?

These are heuristics over the instruction list, not a full parse — heredocs, line continuations inside strings and BuildKit-specific syntax may confuse them. For CI, run hadolint as well.

Does Dockerfile Linter work offline?

Once the page has loaded it keeps working without a connection. A few tools fetch a library on first use, after which they are cached.
